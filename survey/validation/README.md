# Reliability check: blind re-coding by two other language models

The original survey coding (`../data/codes_A.tsv`, `codes_B.tsv`) was done by Claude Opus 5.5. Here every record is re-coded, blind, by **Gemini Flash 3.6** and by **Perplexity** (default model, which the service does not disclose). Agreement is then computed on the same records. The notebook structure follows the workflow Perplexity proposed (`WORKFLOW_perplexity.md`), with the changes listed at the end.

## Results (2026-09-28)

| | n | Opus–Perplexity | Opus–Gemini | Perplexity–Gemini |
|---|---|---|---|---|
| Trajectory code, planned 10% subset | 75 | 0.86 (0.75–0.94) | 0.84 (0.73–0.93) | 0.87 (0.78–0.95) |
| Trajectory code, all records | 747 | 0.68 | 0.71 | 0.65 |
| Arm B relevance screen | 397 | 0.34 | 0.65 | 0.31 |
| D vs not-D | 747 | 0.43 | 0.43 | 0.45 |

Gemini coded 30 records twice, in two chats, and agreed with itself on 87% of them (κ = 0.77). The original code was the minority code in 64 records; Perplexity's in 92 and Gemini's in 77. Only 10 of the 19 original D codes are held by a majority. No disagreement was adjudicated. The Methods text and the limitations are in `../METHODS_section_2.1.md`.

## Layout

| Path | What it is |
|---|---|
| `CODER_INSTRUCTIONS.md` | codebook as given to any re-coder, with no original codes |
| `LLM_valid/PROMPT.md`, `HOWTO.md` | the prompt used with Perplexity and Gemini, and the procedure |
| `LLM_valid/batches/` | the 15 batches of 50 abstracts sent to the models |

| `data/coding/coding_sheet.xlsx` | blind sheet (748 rows), holding the Perplexity codes |
| `data/frozen/` | frozen sample frame, input hashes, the 2 duplicate draws dropped |
| `src/` | codebook and validation rules, κ and Wilson statistics, loaders |
| `notebooks/` | 00 codebook · 01 freeze sample · 02 blind sheet · 03 validate · 04 distributions · 06 κ (Opus vs Perplexity) |

| `outputs/tables/` | every result table (`kappa_three_coders.tsv` is the main one) |

## Re-running

```bash
python3 perplexity_batches.py import "default model, not disclosed (web search off), 2026-09-28"
python3 three_coders.py "Flash 3.6"
cd notebooks && for n in 03_validate_coding 04_compare_distributions 06_kappa; do
  jupyter nbconvert --to notebook --execute --inplace $n.ipynb; done
```

The notebooks are generated by `make_notebooks.py`. Edit that file, then regenerate; regenerating clears their outputs.

## Changes from the Perplexity workflow and from the protocol

- **No new PubMed draw.** The re-coders code the frozen 2026-09-25 sample, so that κ against the original codes is defined.
- **Duplicates.** Two Arm B records were drawn twice (PMIDs 27959617 and 39505152), so Arm B has 398 distinct records and each is coded once. The one truncated Perplexity row (B238) is left missing rather than guessed, so the three-coder comparisons use 747 records.
- **Warnings, not errors.** Filled detail fields on P records, and missing detail fields on NC/D records, are logged as warnings. Detail κ uses only records where both coders filled the field.
- **κ undefined.** When both coders use a single category, κ is reported as undefined (NaN), not 1.
- **The protocol planned a human re-coder.** This was replaced by two language-model re-coders; the change is logged in `../PROTOCOL.md`.
- **Validation of the original codes.** The validator also found that Opus had filled `level` on 133 P records (harmless), and that PMID 28185406 (A267) is coded D with no scale, observation or anchor.
